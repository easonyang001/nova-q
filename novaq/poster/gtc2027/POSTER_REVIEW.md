## 1. 標題與命名

**海報寫法**：NOVA-Q: Verified LLM Agents From Natural Language and Open Data to QAOA on CUDA-Q

- 🟠 **「Verified」的強度**：我們的驗證是測試式的（突變測試、交叉核對、窮舉小實例），**不是形式化證明**。審查委員如果是形式化方法背景，可能會追問。
  - 建議：口頭說明時用「checked / validated by independent gates」，不要說「proven correct」。標題可以保留，因為 verified 在這個領域常用來指測試式驗證。
- 🟠 **和原論文的關係**：程式碼是在 QuantumQUBO Agent（Mondal & Parvez, ICML 2026 WS, MIT）上延伸的，repo 前 7 個 commit 都是原作者的。
  - 海報已引用 [6]，流程圖下方也寫了「Built on QuantumQUBO Agent」。
  - 但沒寫清楚**哪些部分是沿用的**（前端六個 agent）、**哪些是新的**（資料、驗證、求解後端）。建議在 Workflow 圖說補一句。
  - 作者名單只有兩位。是否需要徵詢原作者或列入致謝，請和老師確認。
- 🟢 名稱 NOVA-Q：在量子／QUBO 領域查過沒有撞名，但 Amazon 有 Nova LLM，不能省略「-Q」。這只是網路搜尋的結果，不是商標查詢。

## 6. Methodology（求解器比較）

- 🔴 **實例有選擇偏差**：縮小版實例是從「**通過驗收的**」agent 模型產生的。所以這些都是正確的模型，結果不代表 agent 的一般狀況。這樣做是合理的（要比較求解器，模型必須正確），但要寫出來。
- 🟠 **規模縮小**：真實題目是 53–456 個實體，QAOA 用的是 3–7 個代表點（9–27 量子位元）。標示「real data」可以，但不能讓人以為 QAOA 解的是原始規模。
- 🟠 **三個重複實例彼此相關**：種子 1、2 是從同一份資料隨機抽 80% 再做 k-means，所以 IQR 帶低估了真實的變異。
- 🟠 **各求解器的預算不一樣**：

  | 求解器 | 樣本數 | 中位數 wall time |
  |---|---|---|
  | SA | 1,000 reads | 0.2 s |
  | SQA | 1,000 reads | 86 s（這輪 CPU 被其他工作占用，第一輪只要約 10 s） |
  | D-Wave QPU | 1,000 reads | 1.7 s（其中 QPU 時間約 0.1 s） |
  | CGA | 3–999 個樣本（一次 10 s 的工作） | 38 s |
  | QAOA p=3 | **10,000 shots** | 65 s |

  所以 P(最佳解) 是每個樣本的機率，比較公平；但「找到最佳解」會受樣本數影響，QAOA 有 10 倍的樣本優勢。
- 🟠 **參數調整不對等**：
  - SQA 的 β=200 是**在 3 題上調出來的**，其他求解器都用預設值；
  - 懲罰權重全部用預設的 floor+1，沒有替各求解器調整，這對 QAOA 和 QPU 比較不利；
  - QAOA 試過 CVaR（α=0.2）和 p=6，都沒有改善，**沒有寫在海報上**。這不必放上去，但被問到時要誠實回答。
- 🟠 **D-Wave 重跑了一次**：第一次的結果被第二次取代（第二次是為了保存每個樣本的能量）。仍然是每個條件只用一次實機結果，但要知道有這件事。
- 🟢 AED 只有 3、6、9 點，因為「每組人數相等」要求 n 能被 3 整除，其他點數沒有可行解。

## 7. Verification Gates（熱圖）

- 🔴 **「five gates before any solver call」**：見第 0 節第 1 點。
- 🟠 **G1 名稱不一致**：清單第 1 點是「Schema & model check: data contract; brute force on a small instance」，但熱圖的 G1 只測了**資料結構檢查**（L1），沒有測「窮舉小實例」那部分。建議清單拆開，或熱圖欄名寫「G1 data schema」。
- 🟠 **樣本數小**：每列 n = 9–18，而且只有 6 個種子、3 次檢查器建置。百分比的信賴區間很寬，例如 n=9 時 100% 的 95% 信賴下限大約是 66%。
- 🟠 **故障是人造的**：D1–D6、M1–M5 是我們設計的，不保證涵蓋 LLM 實際會犯的錯。M1 有兩個子類（row_sum、visit_each_once）**完全沒被抓到**，海報上合併成 60%，看不出來。
- 🟠 **300/300、733/733 的意義有限**：這是「模型通過了**自己這一輪**檢查器」的數字。突變決策是檢查器自己產生的，可能大多是容易判斷的情況。它證明的是「通過驗證的模型和規格一致」，不證明「檢查器會抓到錯誤」。後者是熱圖在證明的事。建議說法改成「no false alarms on 15 verified runs」。
- 🟢 斜線格（範圍外）的設計合理，圖說也解釋了。

## 8. Results（能量差距圖）

- 🟠 **指標要講清楚**：能量差距 = (E − E_opt) / (E_random − E_opt)，取一次執行所有樣本的平均。它衡量的是**整體樣本品質**，所以樣本多、分布廣的求解器（QAOA、CGA）天生吃虧，用「最好的樣本」比較結果會不同。
- 🟠 **D-Wave 37/39**：海報圖說已寫，正確。
- 🟢 QAOA「51–18,000× random」：取的是每題 P(最佳解) 除以隨機猜機率的範圍，計算正確。最高的 18,000× 是在最大的題目上，對應的 QAOA 命中數只有個位數，屬於小數字推估，信賴區間很寬。

## 12. 預期問答（建議答法）

| 可能的問題 | 建議回答 |
|---|---|
| QAOA 輸給所有退火器，用 CUDA-Q 的意義是什麼？ | 我們的貢獻是驗證流程。CUDA-Q 讓同一個驗證過的 QUBO 可以直接拿去跑閘模型演算法，而且在 GPU 上快 400 倍；淺層 QAOA 落後退火法是已知的現象，原因是懲罰項讓可行解比例偏低，下一步是限制保持型 mixer。 |
| 9–27 量子位元是不是玩具？ | 原始題目是 53–456 個實體，已經由 agent 交給退火器解。縮小版只用在 QAOA，因為量子態模擬的記憶體會指數成長，這正是 GPU 和多 GPU 要解決的問題。 |
| 驗證會不會誤報，把正確的模型擋掉？ | 15 次通過驗收的執行中，300/300 個合格決策都被接受；故障注入的 18 次乾淨檢查中有 3 次誤報（同家族和跨家族各 3 次，但發生在不同題目上）。 |
| 開發集上的數字會不會過擬合？ | 會，所以海報標明是 development set。修正原則是只做通用修正，不寫特定題目的規則；驗證集和測試集正在建。 |
| 和 QuantumQUBO Agent 的差別？ | 原論文從使用者給的測試案例做自我修正；我們從開放資料自己建實例，並加上不需要標準答案的獨立驗證關卡和多求解器後端。 |
