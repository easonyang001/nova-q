# 端到端驗收（自主模式）

目的：使用者提出真實需求後，系統能不能可靠地走到可用成果。分別回報**資料正確率、模型正確率、最終交付率**。

## 規則

- **系統只拿到**一句需求，以及每一輪 Clarifier 提問時同一段固定回答。回答只含 B 類使用者設定（數量、範圍、距離定義），不含欄位名稱或公式。
- **系統看不到**這個目錄（`truth.py`、`judge.py`）和 `results/acceptance_truth/`。驗收標準只從原始需求和官方原始檔寫出，不依賴系統產生的模型或 Checker。
- 每次執行都從空白開始：沒有模型、資料快取或 LLM 快取。**每一組（包括直接 LLM）都要自己上網找資料**，不提供任何檔案。
- **即時資料**（YouBike）：如果這次執行下載的是官方即時資料，就用它自己下載的那份檔案重算標準答案；沒有用官方來源的，用事先下載的快照判定，並在紀錄裡註明。
- 批次開始時，`manifest.json` 記錄程式與 prompt、驗收程式、標準答案的 SHA256。中途若有任何一項改變，執行器會拒絕繼續，必須換新的 tag 重跑。
- 失敗全部保留，不重跑、不手動修正。第二個人工確認點（核准資料）在批次中自動核准，核准得對不對由驗收判定。

- 台灣：`python -I acceptance/truth.py results/acceptance_truth/raw_20261011 results/acceptance_truth/truth_20261011.json`

## 判定（`judge.py`）

判定程式不會當掉：意外的輸出會被判為不通過或「無法驗證」。

- **資料**：系統的決策對象要一對一對應到真實實體，比對方式**先用 id 或名稱**，再用座標補對不上的。用名稱對上的實體，座標仍要在合理範圍內，不能和其他實體完全相同。報告列出：
  - 實體數量；
  - 缺了哪些、重複哪些；
  - 座標是否在該題的城市範圍內；
  - 有人口的題目：每個區域的人口是否完全相符、總數是否等於官方數字；
  - 柏林題：居民總數必須等於官方的「全部居民」或「尚未被服務的居民」其中之一。
- **模型**：
  - 隨機產生 30 組符合原始要求的方案（選點題有一半刻意挑互相靠近的點，讓服務範圍重疊），固定決策變數，用 MILP 求輔助變數的最佳值，算出模型目標，再和由原始資料獨立算出的真實指標比較排序，Spearman 相關係數需至少 0.9；
  - 故意產生違反原始要求的方案（多選一站、少選一站、某站走兩次、組別人數不均），模型必須判定為不可行。
- **交付**：交付的解要滿足原始要求，而且用原始資料重算的真實品質，與參考解的差距在 10% 以內。參考解如下：
  - 充電站：貪婪選點；
  - 路線：最近鄰再加 2-opt；
  - 分組：貪婪分組再兩兩交換；
  - 倫敦、柏林：MILP 求出的精確最佳解。

  交付的方案來自退火機或系統內建的簡單基準都算，但兩者分開報告。

## 執行

```bash
python scripts/preflight.py --tag e2e_main_YYYYMMDD          # 全部 PASS 才開跑
python scripts/run_e2e_batch.py --tag e2e_main_YYYYMMDD --repeats 3 \
    --arms direct pipeline no_repair full full_rag full_noweb
```

六組設定（R0～R3、R3＋RAG、R3−上網）的定義寫在 `cases.json` 的 `arms`；分析計畫見 `PREREGISTRATION.md`。

每題都使用固定預算：
- Clarifier 最多 3 輪；
- Modeler 最多試 4 次；
- 資料搜尋最多 2 輪、最多下載 4 份；
- 求解用 CGA、預設 penalty，最多 3 次呼叫；
- 完整系統最多 1 次「資料→模型」修復，加上 2 次求解前後的修復。

輸出在 `results/<tag>/<組別>/<題目>_r<次>/`，`record.json` 記錄每個階段的成敗、判定結果、成本和判定用的是哪一份標準答案。
